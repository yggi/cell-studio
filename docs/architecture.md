# Architecture

What lives where in Cell studio, and how source text becomes sound. Language: [language/overview.md](language/overview.md). Views: [ui/graph.md](ui/graph.md). Known gaps: [limits.md](limits.md). History and decisions: [MEMORY.md](MEMORY.md).

## Hard rules

- The code text is the single source of truth. Every graph edit is a rewrite of that cell's own line (`src/engine/edit.ts`: `setAttr`, `setFlag`, `setShift`, `setOff`, `setBraid`, `setTiming`; pure string to string, comments kept).
- `src/engine/` and `src/layout/` are pure TS: no DOM, no Tone. They run in node under vitest.
- Theme values come from `src/app.css` and `src/ui/theme.ts` only (theme.ts mirrors app.css for colours computed in code; change both together).

## Data flow

```
code text (ui/state/piece.svelte.ts `Piece.code`)
  parse()              engine/parser/     -> ParseResult (AST types: ast.ts)
  compile()            engine/compiler/   -> CompileResult (cells, clocks, outputs, tapes, diagnostics)
  plan(result, shifts, muted)  engine/realize.ts -> Plan
  player.load(plan, source)    audio/player.ts
  every window: engine.window(from, 0.25)   audio/engine.ts -> engine/schedule.ts windowAt -> Window
               (plain data: Played[] — at, dur, voice, freq, bends, gains, levels, output — and moving tapes' speeds)
  retime(window, audioTime, secPerQuarter)  engine/schedule.ts: onto the audio clock
  voices.sync(result, shifts, muted)  audio/voices.ts: carries out wiring(result, muted) (audio/wiring.ts)
  voices.play(note)    audio/voices.ts (Tone.js; createVoices, parts in audio/voice/); the note names its output,
                       and opens the taps of the mixes it goes through (wiring's `taps`, audio/gate.ts)
  also: compile result -> buildGraph (engine/graph.ts) -> layout/ -> ui/ drawing
        compile result -> flows (engine/flows.ts): where sound goes, read by routing and by wiring
        compile result -> routing (engine/routing.ts), liveAt (engine/live.ts) -> what the graph draws as sounding
```

The engine behind `engine.window` is local (in this thread, on the app's plan: the default) or a Web Worker (`?engine=worker` or `localStorage['cell-studio:engine'] = 'worker'`): `audio/engine.worker.ts` runs `engine/host.ts`, which compiles the same piece from its source, plans it, mirrors every hand (`grab`, `reset`) and answers windows by message; a window it doesn't answer within 40 ms is worked out locally. Measured, the worker doesn't lighten the main thread (scheduling is < 1 % of it; see [notes/15-engine-worker.md](notes/15-engine-worker.md)), so it stays opt-in; it's the message-shaped seam for moving the live state off the main thread later. Views read the sound through one `LiveSource` (`audio/live.ts`, implemented by `Player`): notes, spectra, waveforms, tapes, and hands (strike, damp, bow, scrub, grab).

`compileSource(src, env)` = parse + compile. `codeShifts(result)` gives the shifts written in the code; live hand-turns replace them. `shiftsAt`, `clocking`, `timeMap` (clocking.ts) make every stepped cell's shift a function of time. `Player` (a 16th-note window scheduler on the Tone transport) swaps programs in whole at the next window. `renderOffline` (audio/render.ts) plays the same plan into a buffer.

## src/engine

- `parser/` (`parse`, `pieceMeta`), `ast.ts`: one cell per line, read by construct:
  - `scanner.ts`: a line (continued lines joined), names, numbers, references with picks, shifts and `^n`.
  - `cell.ts`: a cell's line, its attributes and its braid in any order.
  - `braid.ts`: steps (numbers, rests, chords, choices, cells) and their modifiers.
  - `generators.ts`, `free.ts`, `values.ts` (`step=`/`loop=`, `map=`), `mix.ts` (a mix chord, kept as an expression).
- `attributes.ts`: every attribute in one table (what it means, takes and acts on; its doc page); the parser, compile, the node editor and the docs test read it.
- `algebra.ts`: the mix algebra ([decision 006](decisions/006-mix-algebra.md)): a mix's expressions typed by sort and distributed, one binding per voice.
- `program.ts`: a compiled program: its types (`ResolvedCell`, `Clock`, `Output`, `CompileResult` …), the `ROOT` grid, `MAX_EVENTS`, `BODIES`, `codeShifts`, and small readers of a cell (`pickIndices`, `pickSteps`, `adsrOf`, `isPositional`).
- `helix.ts`: helix arithmetic, reading a program through the shifts: a cell's entries as turned (`entries`, `lookup`, `period`), a number resolved down to a grid (`resolveIn`, `resolvePitch`, `tableChain`), positions as pitches and colours (`semitones`, `positionHue`, `freqHue`, `gridName`).
- `compile.ts`: `compile()` and `compileSource()`; the phases are `compiler/`, run in order by `compiler/index.ts`. Each takes what it reads and returns what it makes (the cells pass along, each refining phase handing on a new map; the read-only phases get them read-only); they share only the diagnostics and the environment (`context.ts`):
  - `declare.ts` (declarations, the default grid, `scale()` tables, `over=` chains) → `sorts.ts` (what each cell is, a mix typed: `algebra.ts`) → `resolve.ts` (cells as helices, `&refs`) → `bindings.ts` (kits, the sound card's channels, mixes expanded, voices) → `clocks.ts` (clocks, each cell's rate) → `checks.ts` (what physical and sounding cells refer to) → `outputs.ts` (one per voice binding, articulated) → `limits.ts` (the caps: notes a cell expands to, notes a second it starts) → `display.ts` (display tables, exciters) → `roles.ts` (attributes where they do nothing).
  - `tables.ts`: reading declarations as tables (`tableOf`, `lengthOf`, `unitsOf`).
- `realize.ts`: `plan` (every output's braid flattened once), `eventsBetween` (the notes that start in a window: tapes' echoes, laws, selectors, chance); the gates the scheduler uses (`outputSounds`, `endOf`, `picksNow`, `liveGains`). Its parts:
  - `clocking.ts`: time. `timeMap` (swing, positions in a bar, a motor or a belt), `clocking` (a program's clocks at a moment), `shiftsAt` (tables turning), `playedCells`, `physicsOf`, `tapeMotion`.
  - `flatten.ts`: a braid as numbers in its own steps (`flatten`, `unitsFor`, `stepsOf`, `StepEvent`).
  - `series.ts`: a cell read as a stream over a note (`modulation`, `levelSeries`, `paramTracks`, `pitchOf`).
  - `values.ts`: what a cell sounds at a moment, for views (`valueAt`, `valuesAt`, `notesAt`).
  - `ids.ts`: graph ids (`cellId`, `edgeId`, `stepEdgeId`), shared with `muted` sets.
- `flows.ts`: where sound goes, one description (#132): every flow between cells (a mix's entries, a sound card's channels, a selector's parts, a mix onto a tape, a tape under a head, `excite=`, `couple=`), with its graph edge id. Read by `routing.ts` (the graph's states) and by `audio/wiring.ts` (the connections `voices.sync` makes), so the two can't drift apart.
- `routing.ts`: what takes part in the sound, as graph nodes and edges: `routing` (what can sound), `liveRouting` (what does now), `drawn` (through petals), `nodeStateOf`/`edgeStateOf` (off, unrouted, on, idle, live). One model for nodes and edges: [ui/graph.md](ui/graph.md#states). `live.ts`: `liveAt`, the live view (playheads, lit table entries, and the live routing).
- `schedule.ts`: what to play next as plain data (`windowAt`, `tapeSpeeds`, `retime`, `isPhysical`). `host.ts`: the engine as a message handler (`createHost`: load, window, grab, reset; `planOf`, `grabIn`), what the worker runs.
- `plugins.ts`, `builtinPlugins.ts`: plugins, the app's own and a piece's ([decision 011](decisions/011-plugins.md), [language/plugins.md](language/plugins.md)): `splitPlugins` cuts the `=== plugin name ===` blocks out of the text (blanked, so lines keep their numbers) and reads each manifest; the drawing stays code in `ShowPlugin.code`, run by `ui/plugin.ts` only. `builtinPlugins.ts` is the bundle the app ships (the sun: the same block syntax, as data, so compile knows its manifest everywhere; a piece can't take its names). `parse` carries a piece's, `compile` puts both in `CompileResult.plugins`, `layout/show.ts` (`pluginOf`) knows which cells they draw.
- `edit.ts`: line rewrites. `graph.ts`: `buildGraph`, the graph of exactly what is written: each edge a wire (port, band, width, along the flow) carrying its transforms. `transform.ts`: what a tap does to what it carries (a pick, a delay, degree, inverse, a transposition, a gain, a rate), as data, and the edge's label drawn from it (`edgeLabel`).
- `duration.ts`: piece length / loop cycle (`pieceTime`, `sections`, `mainTempo`, `anchoredAt`). `held.ts`: `free()` values moved by hand, by their place in the code.
- `shorten/`: Shorten (`shorten`, `shortenAll` in `index.ts`), one rule a file (`runs`, `phrases`, `fractions`, `same`) over a shared `harness.ts`.
- `physics.ts` (motors, friction, belts: warps a clock's time map), `fm.ts` (Bessel spectrum), `wave.ts` (a voice's braid as waveform).
- `dough-params.ts`: sound parameter names. `order.ts`: the library's order of examples (`ORDER`: a new file in `examples/` needs an entry). `presets.ts`: `PRESETS`, every `examples/*.cells` read at once (one plain-text piece per file, the format users save), for the tests; `examples.test.ts` checks every file compiles clean and has a title, tags and `level=`, and that the index below is current. The app doesn't use it: `src/examples.ts` has the build-time index (`virtual:examples-index`, made by `tools/examples-index.ts` through a plugin in `vite.config.ts`: title, description, tags, size, time, bytes, and the graph in miniature from `layout/miniature.ts`) and `loadExample(key)`, which fetches a piece's source (its own chunk) when it's opened; only the first piece is in the first bundle. `fiveto12.ts`: the day-long cycle. `ladder.ts`: the tutorial as a ladder, `LADDER` (the forms each rung introduces) and `formsUsed` (which forms of the reference a piece uses, read from what it parses to); `ladder.test.ts` checks every rung against it ([display.md](language/display.md#the-tutorial-rung)). `tags.ts`: the kinds of tag (genre, artist, tutorial, topic) and the examples' vocabulary.
- Tape and resonator have no file of their own; they live in parser/compile/realize/clocking (tests: `tape.test.ts`, `resonator.test.ts`).

## src/layout (pure drawing logic)

`layered.ts` (Sugiyama rows), `physics.ts` (d3-force `ForceLayout`: holds the layout's state, `state.ts`, and runs it by phase), `options.ts` (`LayoutOptions`, the defaults), `start.ts` (where a graph starts: `flowRanks`, columns, the layered start, new nodes, `rowsKey`), `insertion.ts` (a start by insertion), `forces.ts` (each force's step: bends, spread, kinds, clusters, notes, turntables, uncrossing), `aims.ts` (a tape's heads), `nets.ts` (a net's tree and its springs, the taps, a meter's net), `junctions.ts` (a product's junction: the graph folded for the forces, the dot set on its voice's rim), `placement.ts` (meters placed last), `cellview.ts` (grid or braid view of a cell), `track.ts` (a braid's track: its splices as bulbs, one curve, the hand bent into them), `show.ts` (`show=`), `describe.ts` (sentence and connections), `labels.ts` (label templates), `library.ts` (pieces/tags graph), `miniature.ts` (a piece's graph, small, for the library: in the examples' index at build time), `clusters.ts` (a tag's wash, in both graphs), `geometry.ts` (SVG paths), `wheel.ts` (one geometry for every wheel: hub, rim, disc, playhead), `dial.ts` (wheel maths, labels fitted to a wheel), `spectrum.ts` (polar waterfall), `belts.ts` (pulleys and belts).

## src/audio

`player.ts` (Player: transport, windows onto the audio clock, hands; implements `LiveSource`), `heldTapes.ts` (sound tapes while stopped: held where they stand, moved by hand), `device.ts` (the audio context: made as `tuning.ts` says, and what it reports to the performance overlay), `engine.ts` (`Engine`: `LocalEngine`, `WorkerEngine`, `chooseEngine`) and `engine.worker.ts`, `live.ts` (`LiveSource`, what views ask of the sound), `voices.ts` (createVoices, VoiceBank: builds the piece's voices, mixes, tapes and resonators and makes the connections `wiring.ts` lists), `wiring.ts` (pure: the connections `sync` makes, from `engine/flows.ts`, with `off` applied once: a connection needs its ends and every cell on its flows on; `wiring.test.ts` holds it equal to the flows for every example; and `taps`, which mixes' wheels each output's notes open: a mix's wheel hears what goes through it, #77), `gate.ts` (a mix tap that opens while the notes going through it sound), `voice/` (its parts: `voice.ts` a voice's chain and a note on it, `resonator.ts`, `tape.ts`, `noise.ts`, `params.ts` moving parameters, `nodes.ts` the typed bridge between Tone's nodes and native ones), `clock.svelte.ts` (reactive transport position), `render.ts` (offline render, WAV, `loudness`, `sampleHash`, `blockLevels`), `ticker.ts` (`onFrames`: the one frame loop for the transport clock and every live view, each at its own interval, eased under load; sound is unaffected).

Scheduling: Tone's context is made with `latencyHint: 'balanced'` (about 55 ms made-to-heard on the phone measured, `audio/tuning.ts`) and a 0.3 s look-ahead (0.12 s for pieces with hands, so a grabbed motor answers quickly); the sound itself runs on the audio thread, so a busy main thread delays scheduling (covered by the look-ahead), not the sound. The pictures are drawn from the position of what is *heard* (the audio clock held back by the output timestamp's lag, `audio/heard.ts`, read from the one estimate of the audio clock against the page's, `midi/clock.ts`, which MIDI out's timestamps use too), not of what is made. Live views refresh about 24 times a second (spectrum wheels 15, and only while on screen) from one shared frame loop (`audio/ticker.ts`) and stretch their interval when frames come late. Details and measurements: `tools/profile/README.md`.

## Elsewhere

- `src/ui/`: Svelte components by role. Graph and nodes: `Graph`, `MiniGraph`, `LibraryGraph`, `FitView`, `CellNode`, `PieceNode`, `VoiceNode`, `MaterialNode`, `ScopeNode`, `PluginNode` (a cell a plugin of the piece draws: its dial, its name; `PluginTree` draws what `draw` returns, `plugin.ts` runs the code, `pluginTrust.svelte.ts` says whether it may (built-in: yes; a piece's: only if the user chose), `pluginView.ts` is what it is given, `pluginTree.ts` the allow-list), `CellLink`, `BeltEdge`, `PulseEdge`, `GraphLegend`. Cell drawing: `CellGlyph`, `WaveGlyph`, `SpectrumWheel`, `ScopeView`, `PieceWheel`. Editing: `Editor`, `EditPop`, `StepEditor`, `HubEditor`, `Keypad`, `Picker`, `QuickPick`, `CellSheet`, `CellFacts`, `ParamRows`, `Free*` (`FreeControl`: a free() as a slider, keypad or text; `free.ts`: its words), `ForcesPanel`, shared `Shorten`, `Transport`. Shared parts, `ui/kit/`: `Dialog` (a modal pop-up: scrim, panel, focus held) and `attach.ts` (attachments: `trap` a modal's focus, `longpress`, `onScreen`). Helpers: `snapshot.ts` (what the graph draws as one value: a piece's program, graph, shifts and routing, and the one place that drops what the program doesn't have), `flownode.ts` (which node draws a cell, and how large), `flowedges.ts` (pure, tested: an edge's look, what it carries by one lookup by band and port, and every flow edge of a snapshot), `theme.ts`, `highlight.ts`, `suggest.ts`, `tags.ts`, `context.ts`, `types.ts`, `entries.ts`, `wakeLock.ts`, `perfSwitch.ts`.
- `src/theory/modes.ts`: names, modes, `scan`, hues. `src/library.ts`: saved pieces (localStorage) and `.cells` files; always reports unavailable storage instead of failing. `src/storageKey.ts`: the localStorage key of a kept setting or the saved pieces, its own in a PR preview ([testing.md](testing.md#run)).
- `src/midi/`: Web MIDI's browser glue: the connection (`access.ts`), adopting the ports chosen as they come and go (`routing.ts`), reading a message (`surfaces.ts`), sending the notes played (`out.ts`, `MidiOut`), a device's drum map (`drum-presets.ts`), and the audio clock against the page's at the heard moment (`clock.ts`); the `Midi` class in `ui/state/midi.svelte.ts` holds the settings and is the player's `NoteSink`; MIDI learn is `ui/learn.ts` with the `Learn` class in `ui/state/learn.svelte.ts`. What a played note is as MIDI (its key and cents, velocity, bends, channel; a kit member's drum note) is pure, `engine/midi.ts` ([ui/midi.md](ui/midi.md)). `audio/` imports one module of it, `midi/clock.ts`: `audio/device.ts` `contextClock` keeps one estimate per context, which the pictures' lag (`heardLatency`) and MIDI out's timestamps both read; `midi/clock.ts` imports nothing of `audio/`.
- `src/ui/state/`: the app's state, as classes with rune fields, shared through one context (`studio.svelte.ts`: `setStudio`/`getStudio`). `Piece`: the code (the only writer of it: every edit goes through `engine/edit.ts`), what it compiles to, the last version that compiled, held `free()` values (`engine/held.ts`). `Playback`: the `Player` fed the piece's plan, where play starts, reset, what hands did (`sound`, the `LiveSource` the views read), the screen wake lock (`ui/wakeLock.ts`). `Library`: the cards (`ui/entries.ts`) and what's open. `View`: the tab, the drawer, the performance overlay's switch (`ui/perfSwitch.ts`), the picker's message. `Studio`: what takes more than one of them (opening a piece, saving, rendering, the overlay's test) and `window.cellStudio` (`src/debugHook.ts`). `GraphLayout` (`graphLayout.svelte.ts`): the graph as laid out, for `Graph`: the snapshot drawn (`shown`), the flow's nodes and edges made from it, the `ForceLayout`, pins, petals, bends, taps and the meters' nets; `sync()` takes the next snapshot and swaps all of it at once, so a node or an edge is never drawn against another piece's program (`ctx.program` is the snapshot's). `Piece` and `GraphLayout` run in node (`piece.test.ts`, `graphLayout.test.ts`: the switch *Baustelle* → *Baustelle II* → *Twinkle*).
- `src/App.svelte`: makes the `Studio`, shares it and lays out the page; `Transport`, `Picker` and `FreePanel` read the context, `Graph` still takes props, and hands its components one `GraphContext` (`ui/context.ts`: the snapshot, the layout's bends and taps, the live state, and the sound as `ctx.sound`). `src/main.ts` mounts it.
- `tools/`: Python generators (`bwv847.py` writes `examples/bwv847.cells`; `kern2cells.py`, `counterpoint.py`) and `tools/bwv847.reference.json` and `tools/profile/` scripts; `smoke.mjs` with `smoke-pick.ts` (the smoke test, [testing.md](testing.md)). Python deps: `pip install -r tools/dev-requirements.txt` (music21).
- `.github/workflows/`: `ci.yml` (check, test, build, deploy to gh-pages from `main`); `smoke.yml` (start every piece and play a set covering every kind of sound, on every non-draft PR); `dependabot.yml` (weekly npm and actions).

# MIDI

MIDI on this device: the connection, the ports, and All notes off (#203, the epic; this page grows with it).
Nothing is written into a piece: what a device is, and which knob moves what, belongs to this browser, not to the code.

- **Where.** *MIDI…* in the picker's **Files** menu opens the dialog (`src/ui/MidiDialog.svelte`): Connect MIDI, then Refresh ports, the output (*No MIDI output* or a port) and the input (*No MIDI input*, *All inputs* or a port) to use, and All notes off. Under them, in words, what was found or why there is no connection: no Web MIDI in this browser (Safari, Firefox without its add-on), or access blocked (a denied prompt, an iframe). Without MIDI everything else works as before.
- **Kept.** The ports chosen are kept in this browser by id and by name (`storageKey('cell-studio:midi')`). A port chosen before is connected again on load without a click, since a permission already granted needs no gesture; a first visit asks for nothing until Connect.
- **Unplugged and plugged in again.** Every change of the ports adopts the chosen ones again, since a port plugged in again is a new object: the output by its id, or, when that id is gone, a port with the same name (ids change on replug on some systems), and the input listened to anew. A chosen port that is absent shows as *Not connected*.
- **All notes off** sends CC 123 on every channel sent on since the last time (on all 16 when none was), and forgets them. It runs by itself when the tab comes back into view, since a tab frozen while hidden can leave a release unscheduled and hardware sounding.

## MIDI learn

A controller's knob, fader or pad moves a `free()` value exactly as its slider does ([../language/free.md](../language/free.md)); nothing is written into the piece.

- **Learn.** With MIDI connected and an input chosen, every `free()` control (the drawer and a cell's sheet; not a text) has *Learn*. Press it, then move a knob or press a pad: the next control change or note-on binds to it (Esc, or *Learn* again, cancels). A bound control shows its knob (*CC 7*, *note 36*, *CC 7 ch 2* off the first channel), and *Forget* (×) lets go. A knob learned for a second control leaves the first. The MIDI dialog says how many controls of the open piece are learned, with *Forget all*. A wait for a knob ends unbound when its control goes (its sheet closed), another piece is opened (or this one renamed), or the input goes; Esc is then everyone's again.
- **Moving.** CC 0–127 runs from `lo` to `hi` through the control's own scale (`src/ui/free.ts`, `freeAt`/`freePosition`, which the slider uses too): straight in the slider's steps (whole bpm for tempo), logarithmic for a frequency or a rate (a setting in Hz such as `lpf=`, `hpf=`, `tone=`, `wanderhz=`, which `src/engine/attributes.ts` marks; a clock's `step=` or `loop=` not in bpm) over a positive range of three octaves or more (`200..5000`: the middle is 1000), both ends exact; any other setting (`drive=`, `index=`) runs straight. The value then goes to `piece.hold`, as the slider's does, so it plays until kept and Stop lets go of it.
- **Choices.** A labelled `free()` (a keypad, a `meter()` choice) takes a knob in equal parts, one a choice; or pads: the pad learned picks the first choice, the pads above it on its channel the next ones (sixteen pads for a telephone keypad). On a slider, pads step from `lo` the same way.
- **Nothing jumps.** Soft takeover: a knob that isn't where the value is leaves it until it passes through it (or lands within a knob's step of it); until then the slider shows the gap, a band from the value to a mark where the knob is. Once something else moves the value (the slider, Stop, Keep, opening the piece again), the knob takes over afresh.
- **Cost.** Each hold compiles the piece again, so a fast knob holds at most once an animation frame per control: the last value before the frame. A tab that draws no frames (hidden, or behind another window) while MIDI keeps arriving holds within 50 ms instead.
- **Kept.** Bindings are this browser's (a controller is a device), kept by piece title and by the `free()`'s place as its cell and what it sets (`bar/step`, `fx/param:lpf`; a second of a kind in one cell `mix/gain#1`), not by its place in reading order, which an edit above it moves (`storageKey('cell-studio:midi-learn')`). A piece renamed (its title changed) starts with none; another browser has none. A renamed cell loses its bindings, and so does an unnamed one, `&( … )`, which is named by its line and column: a line inserted above it, or text before it on its line, moves it. They bind, they hold nothing, so Stop clearing what was held leaves them.
- **Echo out.** *Send a slider's moves back to its knob* in the MIDI dialog (off by default) sends a learned CC to the output when its slider or keypad is moved by hand, for controllers with motor faders or LED rings. A controller that sends it back moves the value to the knob's nearest of its 128 steps, so with echo on the slider is quantised to 128 steps (some bpm of a wide range can't be reached).

## The code

`src/midi/` is the browser glue (`access.ts` the Web MIDI connection, `routing.ts` adopting the ports, `surfaces.ts` reading a message, `fixtures.ts` the fakes the tests use instead of a device); `src/ui/state/midi.svelte.ts` is the `Midi` class in the `Studio` context. Much of it is lifted from Jambot (`yggi/jambot` @ `8cdb6b8`); each lifted file says from where. MIDI learn: `src/ui/learn.ts` is the pure part (a message's knob, a `free()`'s place, pads, soft takeover, what is kept), `src/ui/state/learn.svelte.ts` the `Learn` class in the `Studio` (it hears the input through `Midi.hear`), `LearnButton.svelte` the control's button, `LearnSettings.svelte` its part of the dialog.

# Changelog

What changed in Cell studio, newest first. The app is deployed from `main` on every push, so
this lists user-visible changes; each release (a version bump in `package.json` and a `vX.Y.Z`
tag) gathers the entries under *Unreleased* beneath its own heading. The version and commit of
the running build are shown in the piece picker's **Files** menu.

Format: [Keep a Changelog](https://keepachangelog.com/). Add a line to *Unreleased* in the PR
that makes the change. Also note changes to the language that could affect saved `.cells` pieces.

## Unreleased

### Changed
- A pitch drop is a pitch shape (#30): `pitch=0..30 * &(map=adsr 0 .04 0 0)`, a range in semitones scaled by an envelope in seconds, written like the moving parameters (`lpf=110..3800 * &fenv`). It replaces `penv=30 pdec=.04`, which still plays, with a warning naming the new form. The 16 examples that used it (19 voices: kicks, the Metronome's clicks, Baustelle's basses) are rewritten and render the same (golden renders, all 52 pieces). Saved `.cells` pieces play as before.
- The graph keeps a piece's tags apart (#27): each tag (two cells or more) is laid out first as a block of its own, then the piece around it, and the hubs every part meets (the meter, a selector, a mix) pull a cluster as one instead of pulling its cells into the other clusters. Over the examples, overlapping clusters 50 → 31 and cells inside another tag's cluster 152 → 58; the meter's edges cross more (crossings 105 → 121). Only pieces with tags inside them change. **forces** has the new strengths under *clusters*. Saved `.cells` pieces are not affected.
- The graph (#27): a turntable's name (tape, motor, belt, resonator) sits on a pill like a cell's, so an edge or edge label that passes it runs underneath, not through the text. Saved `.cells` pieces are not affected.
- Wheels (#107): the playhead is white with a dark edge (it was the live edges' yellow, and got lost where they cross); a spectrum at rest shows its partials brighter, inside a rim; an envelope names its values on its curve (A 3 ms, D 180 ms, S 10 %, R 60 ms) instead of four bare numbers; a braid's sheet writes long numbers to three figures (2.3429 → 2.34; the code keeps what you wrote). Saved `.cells` pieces are not affected.
- The graph (#27): a tape's heads face what they connect to. The heads keep their spacing round the wheel, but the wheel is drawn turned (the write head is no longer always on top), so each edge leaves its head straight out, towards what that head records or plays (Echo Tape, Sound on Tape, Test Tones on Tape, Resonanz, 5 to 12). Saved `.cells` pieces are not affected.
- The graph untangles more (#27): crossing edges push apart harder and edges pull a little less tightly, so the examples cross about a quarter less (106 crossings over the library instead of 142; BWV 847 28 → 9, Cellscape 33 → 26, Pop 7 → 3), for about 6 % more room. Every piece's graph moves a little; the library's miniatures with it. The old strengths can be set in **forces** (crossing push 0.3, contraction 0.9). Saved `.cells` pieces are not affected.
- Mixes follow one algebra ([decision 006](docs/decisions/006-mix-algebra.md), #10). The voice of a product is the factor that is a sound, wherever it's written, so `&lead * &theme` is `&theme * &lead`, and `(&theme * &vib) * &lead` groups as it reads. `+` and `*` are commutative and associative; a number is semitones in a sum and a gain in a product, in any position. The examples are unchanged (their events are identical). **Saved `.cells` pieces:** a cell played as a voice that has no sound parameter and no audio-rate `loop=` (e.g. `loop=5`, or no `loop=` at all) is now a pitch, and its mix says so with an error; so is a pattern multiplied by its own kit (`&drums * &kit`: mix `&drums`).
- Attributes in the wrong place are warnings now (#10): an attribute on a cell where it does nothing (`swing=` on a voice, `level=` off the sound card, `wow=` without a motor, `ratio=` on a voice no `fm=` names, `title=` on a cell that plays …), `swing=` on a `scan()` meter (it only swings a list or `meter()`), and a word where a number belongs on a cell that isn't a voice (`motor=strong`) said nothing before. Dough's other names (`cutoff=`, `reverb=` …) still work, with a warning naming ours. A misspelt attribute is answered with the nearest one (`stpe=`: did you mean `step=`?), and the list of attributes in that message is complete. The node editor offers `about=`. Saved `.cells` pieces play as before (no example changes: their events are identical); a piece may show new warnings.
- The library opens without fetching or compiling any example (#61): each piece's graph in miniature is worked out at build time and kept in the examples' index, so a piece's text is fetched only when it opens. Until every miniature is drawn: about 1.7 s instead of 3.9 s here, 6.3 s instead of 14.9 s at a 4× CPU slowdown; the first download is about 7 kB larger gzipped. The miniatures look the same. Saved `.cells` pieces and opened files still draw theirs in the browser and are not affected.
- The audio output is tuned for lower latency: `balanced` instead of `playback`, measured on an Android phone with the full latency test at 56 ms from made to heard instead of 280 ms (desktop ~45 ms instead of ~85 ms), with no late or left-out notes on the heaviest pieces. Hands (strike, bow) are heard sooner by the same amount. If a piece clicks on a device, `?latency=playback` brings the old setting back (kept until `?latency=off`). Saved `.cells` pieces are not affected; how a piece sounds is not, only when.
- Library cards (#12): a tap anywhere on a piece's wheel opens it (in the graph: its details); before, a tap on a tag round the rim filtered by that tag instead. Tags are chosen from the chips. The cards' titles use the card's width, the wheel's petals (cells, length) are no longer cut off on a phone, and **Files** sits beside the heading. A piece's details keep the keyboard focus while open and give it back on closing.
- The library, choosing and seeing (#12): the header shows the open piece's place in the library as a path, *kind › tag › piece* (`artist › Neubauten › Baustelle II`), each step a dropdown — a quick way to a neighbour. The cards' tag row (40-odd chips) is one dropdown per kind (genre, artist, topic), and choices in several hold together. In the library's graph the tags organise the layout, grown from the middle: tiny nodes gather by their tags, then grow until the wheel is full, pushing only their neighbours — the library's opening animation (replayed from the kept layout on later visits; still with reduced motion), at the full view each piece is its title, a pill, and zooming in grows its wheel (with its miniature, fetched only then) behind it, its cells and cycle in a row under the title; a phone opens zoomed in to where the titles read, and the shading is one wash per tag, as in a piece's graph (the haloes and shaded lines are gone; a lit tag ties its pieces with lines). The library is laid out afresh once (its kept layout is from the old forces). Saved `.cells` pieces are not affected.
- `bwv847` is written shorter (#82): `tools/bwv847.py` now runs its longhand through Shorten (`tools/shorten.mjs`), so repeated phrases are cells of their own, used exactly or transposed (10,138 → 9,999 characters in the committed file). The notes are unchanged (checked note by note, and the events of every example hash the same); the graph has one more shared cell and a few more crossings (24 → 28). The order convention is written down in `docs/language/display.md`.

### Fixed
- A fast vibrato works in a mix again (#28): a braid turning at an audio rate with no sound parameter (`&vib loop=30 …`) is a pitch in a pitch sum or beside another sound, `(&theme + &vib) * &lead`, as it was as `pitch=&vib`; alone it is still a waveform voice. Since the mix algebra (#111) it was refused as "a sound". This also makes FM writable in the algebra: `(&tune + &op) * &lead`. No example changes.
- Reading through a table of cells says what happens (#29): `&solo over=&tunes` where `&tunes &a &b` lists melodies played only 0s, silently (a table is its numbers; the cells are skipped). It now warns, and says to splice the cells into a braid. Saved `.cells` pieces play as before.
- One geometry for every wheel (#106): a cell's wheel, a spectrum, a waveform and the braid editor share their hub, rim, disc, border and playhead, so they line up side by side; the hub is a little larger on a cell's wheel, the spectrum's ring a little narrower, and the braid editor sits on a disc like the rest with the same playhead and lit step. The braid's line editor (tap a braid's hub) takes the keyboard focus when it opens, keeps it inside, and gives it back when it closes; Escape there closes only it, no longer the cell's sheet as well. Saved `.cells` pieces are not affected.
- Small wheels (#105): a wheel's text fits it at every size. On petals and other small wheels the hub shows its number, or nothing when it can't be read, instead of a label spilling over the rim; the second line, the shift and the beat numbers show from 80 (beats 64) px up; the rim's ticks, notch and playhead scale with the wheel. Library wheels under ~94 px show their tags as a band without names; the braid editor's step labels fit their segments. Saved `.cells` pieces are not affected.
- Wheels (#104): a piece with a single tag shows its tag ring and name in the library again; the sun and the turntables can be turned from the keyboard when stopped (arrows: an hour, a sixteenth of a turn; Enter or Space opens a turntable), and the sheet's turning rim is announced as a slider; a resonator no longer shimmers with reduced motion. Nothing else looks different; saved `.cells` pieces are not affected.
- `off` is off (#76): the WAV export and `cellStudio.measure`/`render` now leave out switched-off cells (they played everything), and in playback a switched-off tape, tape head, resonator, or mix no longer sounds, records, rings or drives a resonator. Pieces with nothing switched off sound the same; a saved `.cells` piece that has an `off` cell on a tape, head or resonator now really goes quiet there.
- What you see matches what you hear (#67): the position, the highlighted notes and the lit cells and edges now follow the sound as it leaves the speaker, not as the audio engine makes it, so they no longer run ahead of it (by 280 ms on the phone measured). The scopes and spectra, which read the signal as it is made, still run ahead of the speaker by the output latency (about 55 ms with the new default). Saved `.cells` pieces are not affected.
- The graph shows what sounds, for nodes and edges alike (#11): cells that sound are no longer drawn dimmed (a cell that moves a filter or a pitch, a part made only of chance choices, a mix used as an instrument such as Sound on Tape's `&dry`, the mix of tape heads that drives Resonanz's pipes); tapes, resonators, motors and scopes now fade too when off or unused; a selector lights only the part it picks now, and the way from it to the sound card; an edge takes a note's colour and pulses only while what it carries plays (a voice in two mixes no longer colours the edge to the one that isn't playing). The sound and saved `.cells` pieces are not affected.

### Changed
- Lighter playback, fourth round: the transport clock and every live view (scopes, spectrum wheels, tapes, resonators) share one frame loop, which spreads the views' redraws over frames instead of letting each run its own, and each clock's timing is worked out once per piece instead of on every lookup. On the test machine the main thread is 1–4 points less busy on most pieces at full speed. The look, the sound and saved `.cells` pieces are not affected.
- Three examples no longer clip: Zelluläre Aktivität is 9 dB quieter (it peaked 7.5 dB over full scale and distorted in its build-up), Pop song 1 dB quieter and Music Box 2 dB quieter, so each peaks under −1 dB. Saved `.cells` pieces are not affected.
- Seven examples had a placeholder `level=0` and now have a measured level, so they sit with the rest of the library at about −24 dB average: Waveforms +0.5, Drunken Sailor −1.5, IDM −0.5, Acid-Cell +0.5, One more Cell −0.5, Ghost-Cells −1 and Cellular Brothers −3 dB (it was clipping; its peak is now −1 dB). Saved `.cells` pieces are not affected.
- Lighter playback on phones, third round: the redraw after each clock tick is about a third cheaper on the busiest piece (wheels recompute only what changed — the lit step, the entries read, the label's bar — and a step that makes an edge glow no longer rebuilds the whole edge list). The look is unchanged.
- The examples are no longer all in the first download: the library is listed from an index made at build time (nothing is compiled to show it), and each piece's text is fetched when its card is drawn or it is opened (the first bundle is about 24 kB smaller gzipped). If a piece can't be fetched (offline, never opened before), it says so instead of opening. Saved `.cells` pieces are not affected.
- Cell studio is now an installable app (PWA): it has an icon and a manifest, works offline after the first visit, and shows "New version ready" when an update is waiting (it never reloads by itself, so a playing piece is not cut off). The build is no longer one `index.html` but normal files with Tone loaded on first Play. Saved `.cells` pieces are not affected.

### Fixed
- Noise voices (`s=white`, `pink`, `brown`) and a resonator's bow (`body=`) no longer draw on `Math.random()`: the noise itself and where each noise note starts in it (from the cell's `seed` and the note's place in the piece, live or rendered) are the same every time, so renders can be compared. Every noise note's grain differs from before, but the sound is the same kind. Tone's reverb and a tape's hiss still use `Math.random()`, and Chromium sums inputs in a changing order, so two renders agree to float rounding (about −180 dB), not bit for bit. Saved `.cells` pieces are not affected.
- A kit's members now use their own `env=`: a drum read through a kit (`&drums over=&kit …`) used to ignore its envelope and ring for the whole step. This changes how **Drunken Sailor**, **IDM: drill**, **Automaton** and **Metronome** sound (their drums are as short as written); the levels of Drunken Sailor and Automaton were re-set to keep their loudness. Saved pieces that read a kit whose members have `env=` will sound different too.
- **Metronome** no longer hisses: its clicks are short tonal ticks (higher and longer on the downbeat, lower and shorter for finer divisions) instead of noise bursts.
- Opening a piece now starts it from rest: the transport stops at 0 and nothing sounds, even if another piece was playing (it used to carry on from where it was) or the new piece has tapes (their hiss sounded as soon as the piece opened).

### Added
- A syntax reference, [docs/language/reference.md](docs/language/reference.md): every form the parser reads (lines, steps, modifiers, references, generators, `free()`, rates, `map=`, attributes, parameters, mixes), what it means and an example. It is generated from the parser's own tables, so it can't drift from what the parser does (#9, #10).
- `about=&cell` (or `about=(&a &b)`) on a note links it to the cells it explains, drawn as fine dotted lines; it doesn't change how a piece sounds or the layout. Every example's card is now one sentence linked to the sound card, and the longer descriptions (how it works, what to listen for, what to touch) are notes beside the cells they explain. No example sounds different.
- The performance report now also lists our own per-frame work (transport + reactive flush, scopes, wheels, …), how long the main thread kept a task waiting, and how many notes started late or were left out; and its verdict flags a low frame rate and long frames even when there are no long tasks.
- Tags have kinds: `genre:jazz`, `artist:Bach`, and a tag with no prefix is a topic. The library shows the names without the prefix, as before; a piece saved earlier with bare tags keeps working (a bare `jazz` or `Bach` is read as the genre or artist, any other bare tag as a topic), so its tags land on the same chips as the examples'. The examples now use a fixed vocabulary of tags (`src/engine/tags.ts`).
- A performance overlay and a copyable performance report for measuring on a real device: open the app with `?perf` (or Files ▾ → Show performance report), press Record, play a piece, Stop, Copy report. See `docs/ui/performance.md`.
- The running build's version and commit, shown in the **Files** menu.
- A favicon.

### Changed
- On long braids drawn coarser (Bach's Prelude and Fugue), the thin border between segments is gone, so their notes show as clear coloured bars instead of slivers between dark lines. Wheels with wider segments keep their border. Under the hood a key turn is far cheaper (the once-a-bar stalls while the Prelude plays: 9 long tasks of up to 100-200 ms in 20 s become 0-2 of about 50 ms); the look and the sound are otherwise unchanged.
- Very long braids (over ~160 segments, in the examples only Bach's Prelude and Fugue) are drawn with coarser segments on the graph wheel: neighbouring steps are merged into one of at most ~2° and show their first note, so the notes of a 1,000-step wheel are visible instead of lost between rests, and a key turn rewrites a third of the paths (Prelude and Fugue: main-thread busy while playing ~55 → ~41 %, longest stall ~150 → ~105 ms). The cell sheet's wheel still draws every step; wheels under the cap, the sound and the code are unchanged.
- Lighter live views, second round (main-thread load while playing, headless at normal speed: Test Tones on Tape 40 → 24 %, Baustelle II 39 → 28 %, Hypercell 42 → 35 %): spectrum wheels are drawn at the size they are seen (zoomed-out wheels are cheaper and refresh less often), a tape's recording ring turns as one group instead of redrawing ~100 lines a frame, resonator and tape animations run at ~30 a second and back off when the page is busy, and scopes no longer read their traces through reactive proxies. The look is unchanged.
- Lighter live views while playing: scopes and spectrum wheels do much less work per frame (about half the main-thread load on the busiest pieces), skip it when off screen or silent, and refresh less often when the page falls behind. The sound is unchanged; wheels are drawn at up to 1.5× (was 2×) the layout size.
- Sound: Tone's default audio context is now closed when the app creates its own, so only one runs (less battery use on Android).
- Tests run without per-file isolation (faster).

### Developer
- Faster checks, with the same coverage: `npm run check` uses the native TypeScript compiler (`svelte-check --tsgo`, `@typescript/native-preview`, pinned; same diagnostics, about a third of the time), the layout and `show=` sweeps in the tests do each piece's work once (vitest about 24 s → 17 s on a cold cache), and the smoke test starts every piece but plays in full only the fewest that between them use every kind of audio node (`tools/smoke-pick.ts`, `npm run smoke -- --list`; `--all` plays every piece): about 2 m 44 s → 1 m 22 s locally. See `docs/testing.md`.
- `?latency=interactive|balanced|playback|<seconds>` and `?lookahead=<seconds>` tune the audio context from the address (kept until `=off`), and the performance report shows the tuning, the made-to-heard latency (output timestamp), the audio thread's load and missed deadlines (`renderCapacity`, where the browser has it) and a per-window worst lateness: the tools for finding how far output latency can be lowered on a device (#67). The defaults are unchanged.
- The performance overlay has a **▶ Run full test** button (#67): it plays four heavy pieces on four audio settings, from today's down to the lowest latency, makes a new audio context for each, and gives one report that names the lowest setting that stayed clean, to find how far the output latency can be lowered on a device. It puts the piece back afterwards and keeps nothing. Saved `.cells` pieces are not affected.
- CI: the smoke test moved out of `ci.yml` into `smoke.yml` and runs only on the PR labelled `candidate` (once on its head, again after each push to it), no longer on every push of every PR and on `main`. `check` stays on all. See `docs/testing.md`.
- Audio refactoring (#15, #9), no change in sound (every example's offline render compared before and after): what to play next is worked out as plain data (`engine/schedule.ts`) behind an `Engine` that runs in this thread (the default) or, opt-in with `?engine=worker`, in a Web Worker; `voices.ts` is split into `audio/voice/` parts behind the unchanged `VoiceBank`, with Tone's wrapped nodes bridged in one typed place; the graph gets the sound as one `LiveSource` object instead of ten callbacks. Measured: the worker doesn't lighten the main thread (`docs/notes/15-engine-worker.md`).
- `tools/golden.mjs` (golden renders: every example rendered offline and compared with a recorded run), `cellStudio.render(source, seconds)` and `cellStudio.engine()`, `ENGINE=worker npm run smoke`.
- Agent workflow (#6): `AGENTS.md` rewritten (what is enforced, what is judgment, what an agent decides alone), the `senior` skill for triaging, reviewing and merging PRs with the owner's approval, a PR template, a SessionStart hook that installs dependencies in cloud sessions, `.claude/settings.json` allowlist.
- CI: a smoke test (`npm run smoke`, `tools/smoke.mjs`) opens and plays every piece in Chrome; `deploy` is a job of the CI workflow and publishes the build CI made instead of testing and building again; a layering test keeps `engine/` and `layout/` pure.
- `tools/profile`: `bursts.mjs`, `burstlines.mjs`, `cellview-time.ts` (what a long task rewrites and spends its time on; what a table turn costs); `engine-time.ts` reads `examples/`.
- `docs/notes/41-prelude-bursts.md`: measured analysis and fix plan for the once-a-bar stalls in Bach's Prelude.
- `TODO.md` is gone: its open work is in the issues (#27–#37), its known limits in `docs/limits.md`, the rest in `docs/`.
- `tools/profile/trace.mjs`: a Chrome-trace breakdown of the browser's own time, with CSS ablation.
- `tools/profile/`: scripts to measure main-thread load while a piece plays (Playwright + CDP) and to attribute it to code.
- `.claude/skills/profile`: a Claude Code skill for using them (measure, attribute, compare before/after).
- CI runs `npm run check`, the tests and the build on pull requests and on `main`.
- `window.cellStudio` (`measure`, `length`, `level`) is documented in the README.
- `.gitignore` covers Python caches, editor files, coverage and logs.
